# Definition of Done — MVP «АвтоЛиквидность»

Этот список сводит требования из исходного промпта, макета `static/mockup_original.html` и замечания пользователя в браузере. Пункты проверяются на тестовых документах; реальные персональные данные не использовать.

## 1. Запуск и проектные редакции

- [x] Локальный сервер отвечает на `/api/health`, UI открыт в браузере, Swagger доступен на `/docs`.
- [ ] Docker/Compose собирается и запускается без глобальных установок; локальный venv остаётся документированным вариантом.
- [x] Редакция 1 описана как тестовый функциональный MVP с демонстрационным входом; ограничения внешних источников видны и не маскируются под реальные результаты.
- [x] Редакция 2 имеет явную границу и план технических/организационных требований 152-ФЗ; нигде не заявлено юридическое соответствие без аудита и исходных данных оператора.

## 2. UI и паритет с макетом

- [ ] Сохранены экраны входа, загрузки, истории и просмотра отчёта; геометрия, цвета, типографика и состояния сверены с исходным HTML при одинаковом размере окна.
- [x] Боковая навигация, профиль/выход, возврат в историю, загрузка перетаскиванием и выбором файла работают по реализации; вход/выход проверены в браузере.
- [x] Файлы показывают размер в КБ меньше 1 МБ и в МБ от 1 МБ; список позволяет удалить отдельный файл и очистить всё.
- [x] Список отчёта имеет колонки макета, горизонтальную прокрутку и форматирует госномер с пробелом перед регионом (проверено на таблице).
- [x] Никаких фиктивных цен, спроса, статуса проверки или объявления не отображается как найденный факт.
- [ ] Дизайн и поведение проверены для узкого экрана и обычного desktop viewport; все элементы доступны с клавиатуры и имеют понятные состояния загрузки/ошибки.

## 3. Вход и API

- [x] Демо-вход принимает email/пароль, сохраняет токен в `localStorage`, корректно обрабатывает ошибки сети и выход; вход/выход проверены через UI.
- [x] API проверяет принадлежность отчёта пользователю; неизвестный токен/чужой отчёт не раскрывает данные.
- [x] API имеет схемы/валидацию, понятные HTTP-ошибки, health endpoint и интерактивную документацию.
- [ ] Все критичные ошибки обработки отображаются в UI и сохраняются в статусе отчёта без утечки текста ПД в логи.

## 4. Загрузка и обработка документов

- [x] Принимаются PDF/HTML/HTM до 50 файлов в пакете, не больше 25 МБ на файл; неверные форматы/размеры дают понятную ошибку.
- [x] POST возвращает ID пакета сразу; UI опрашивает статус до завершения, отображает прогресс/ошибку и не блокирует страницу.
- [x] HTML ФССП разбирается структурно без LLM, по каждому `div#rs_act_format`; несколько постановлений и несколько ТС дают отдельные записи.
- [x] В эталонных HTML извлекаются ФИО, долг, марка/модель, год, VIN, госномер, тип постановления, номер/дата документа, взыскатель и IpId; замаскированный VIN остаётся `null`.
- [x] Кириллические VIN нормализуются; footer-подсказки цены/спроса/статуса не становятся данными автомобиля.
- [x] `099_Toyota_Avensis.html` определяется как `removal` и не попадает в активный тип постановления; запись сохраняется парсером.
- [x] PDF с текстовым слоем извлекается через pdfplumber; скан проходит OCR; низкая уверенность помечается для ручной проверки.
- [x] PDF-извлечение через GigaChat работает с ключом из `.env`; пустой ключ и сбой провайдера дают объяснимую ошибку, а не успешный фиктивный результат. Реальный тестовый Audi Q5 PDF вернул одну запись за 13,7 секунды.
- [x] При нулевом результате HTML-парсера применяется текстовый fallback; если в тексте нет записей, отчёт получает явную ошибку.
- [x] Временные загруженные файлы удаляются после обработки (проверено двумя последовательными пакетами по 50 HTML). Готовый отчёт и связанные автомобили сохраняются после остановки и нового запуска приложения на той же SQLite-базе. [ ] Возобновление незавершённых пакетов после аварийного завершения не проверено.

## 5. Рыночные данные, VIN, спрос и приоритизация

- [x] Провайдеры отделены интерфейсом; цена/спрос/проверка VIN передают источник, время получения и статус. При отсутствии провайдера API честно сообщает `not_configured`.
- [x] Средняя цена считается только по валидным объявлениям от настроенного провайдера, ссылка ведёт на конкретное объявление, список объявлений показывает площадку/цену/ссылку.
- [x] Не включаются платные источники без явного разрешения; ApiAd выключен по умолчанию.
- [x] В MVP без разрешённого источника показывается честное «Нет данных», а не моковая оценка. Дром/Авто.ру/Авито/СберАвто считаются подключёнными только после успешного интеграционного запроса.
- [x] VIN-статус не угадывается случайно; «Не проверен» и «Ошибка» имеют отдельную семантику, «Снят запрет» — тип документа, фактический статус «В залоге/Свободно» требует подключённого VIN-источника.
- [x] Метрика спроса определена: используется только поле подключённого источника; отсутствие источника отображается как отсутствие данных, без произвольного процента.
- [x] API отчёта возвращает приоритетные ID без `removal`, с валидными ценой/спросом выше порогов, в порядке мотивационного индекса. UI разрешает выделение только приоритетных авто; API экспорта повторно применяет те же пороги и исключает залоговые автомобили.

## 6. Отчёт, фильтры, выделение и экспорт

- [x] Фильтры «Все/Свободно/В залоге» и спрос действительно меняют строки; раскрытый список визуально проверен, кнопка сохранена в стиле фильтров макета.
- [x] Сортировка цены переключает направление и сбрасывается; фильтры и сортировка работают вместе.
- [x] «Выбрать всё видимое» выбирает отфильтрованные строки; ручной выбор, счётчик и скачивание синхронны. В браузере проверено переключение счётчика 12 → 0 → 12.
- [x] Ссылки открываются с `noopener noreferrer` и доступны только если получен URL; колонка «Спрос» присутствует.
- [x] XLSX экспортирует выбранные разрешённые строки и все требуемые колонки: ФИО, ИНН, долг, VIN, авто, год, госномер, цена, статус, спрос, ссылка, Confidence, тип документа.
- [x] Активные запреты и снятые запреты не смешиваются при экспорте; API и UI блокируют выбор снятых запретов.

## 7. История

- [x] История загружается из API; поиск фильтрует название, ФИО, VIN и автомобиль. Поиск по `Audi` проверен в браузере.
- [x] Сортировка названия/даты работает; переименование сохраняется; открытие строки показывает правильный отчёт.
- [x] Пустое состояние, загрузка и ошибка истории отображаются явно; ошибка предлагает повторить запрос.

## 8. Нагрузка и выпуск

- [ ] Несколько пакетов не теряются; очередь ограничивает параллелизм и не блокирует event loop долгими синхронными вызовами.
- [ ] Сценарий 50 PDF + следующий пакет не приводит к падению; обработка имеет таймауты, ограничения памяти и очищает временные файлы.
- [x] README содержит запуск, `.env`, ограничения текущей редакции, допущения и статус реальных/недоступных интеграций.
- [ ] Полный проход API/UI на `Пример ЗРД.html`, `099_Toyota_Avensis.html`, HTML-наборе 100 документов и 1–5 PDF; результаты сверены с документами.
- [ ] Визуально проверены все экраны и состояния против исходного макета; итоговый архив не содержит `.env`, базу или загруженные документы.

## Остаток до конечного MVP

1. Подключить реальный, разрешённый API объявлений/цен и источник спроса; перед интеграцией Drom нужен `app_id`, Авто.ру требует авторизационный токен. ApiAd остаётся выключенным согласно ограничению бесплатных вызовов.
2. Подключить реальный VIN-провайдер, если нужен статус «Свободно/В залоге».
3. Запустить Docker Engine и подтвердить полный `docker compose up --build`; compose-конфигурация проходит проверку, но демон сейчас недоступен.
4. Завершить полное визуальное сравнение всех экранов на одинаковом размере viewport. Инструмент браузера отклонил открытие локального `file://` макета, поэтому проведена функциональная и текущая UI-проверка, но не пиксельное сравнение.
5. Провести нагрузочный прогон 50 PDF + следующий пакет и полный сквозной PDF-проход 1–5 файлов; реальный LLM/рыночные источники не запускать массово без оценки стоимости и лимитов.

Проверено: 9 автоматических тестов проходят; 100 HTML образцов дали 100 записей (59 ban / 41 removal), долг распознан во всех, один замаскированный VIN оставлен пустым. Сквозной HTML/API (включая два пакета по 50 файлов и очистку временных загрузок), история, XLSX и сохранение отчёта между двумя отдельными процессами приложения прошли; в браузере проверены поиск и массовый выбор. Проверены локальное извлечение PDF, OCR на тестовом изображении и один вызов GigaChat для PDF.

Статус: работа продолжается. Пункт считается закрытым после реализации и подтверждённой проверки, а не после добавления описания. Незакрытые пункты вынесены в оставшуюся очередь ниже.
