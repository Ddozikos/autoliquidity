# АвтоЛиквидность ФССП

Проект ведём в двух редакциях на общей кодовой базе. Это позволяет сохранять единый функционал и не допускать расхождения исправлений.

- **Редакция 1 — функциональный MVP:** быстро проверяем полный рабочий процесс на тестовых документах и подключаем реальные API по мере получения доступов. Пока это локальная разработка, а не эксплуатационная система.
- **Редакция 2 — подготовка к обработке персональных данных:** отдельный набор обязательных требований к архитектуре и эксплуатации, который реализуем после согласования ролей, основания обработки, площадки и срока хранения. Само наличие этого плана не означает соответствия 152-ФЗ.

Подробные границы и пошаговый план: [VERSIONS.md](VERSIONS.md), [редакция 1](editions/v1/README.md), [редакция 2](editions/v2/README.md).

## Запуск редакции 1 на macOS

1. Установите Docker Desktop или Colima.
2. Скопируйте `.env.example` в `.env`, укажите ключ GigaChat и выполните `docker compose up --build`.
3. Откройте `http://localhost:8000`.

Для локального запуска без Docker:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
brew install tesseract tesseract-lang poppler
python run.py
```

Открывайте именно `http://localhost:8000` (не файл `static/index.html` через `file://`, иначе запросы `/api/...` не попадут в backend). Для редакции 1 можно ввести любой email и пароль; вход демонстрационный и не защищает реальные данные.

Файлы SQLite размещаются в `data/app.db`. Не добавляйте `.env`, рабочие базы и реальные документы в архивы или git.

## Что уже работает

- Загрузка до 50 PDF/HTML через очередь одного процесса; HTML ФССП разбирается локально по каждому акту, для PDF используется текстовый слой или локальный OCR и затем GigaChat.
- Хранение обработанных пакетов и записей в SQLite, история, фильтры. В XLSX попадают только выбранные запреты с реальными ценой и спросом не ниже порогов; снятые запреты, залоговые автомобили и записи без нужных рыночных данных сервер исключает повторно.
- Для рыночной оценки предусмотрены адаптеры нормализованных API: `AVITO_PRICE_API_URL`, `AUTORU_PRICE_API_URL`, `DROM_PRICE_API_URL`, `SBERAUTO_PRICE_API_URL`. Каждый endpoint получает VIN, марку, модель и год и возвращает `offers: [{price, url}]`; необязательное поле `demand` — числовой индекс 0–100 от самого источника (или `{score: 0–100}`). Цена — среднее по уникальным валидным предложениям; сохраняется ссылка на предложение, ближайшее к среднему. Источник, время проверки и состояние (`not_configured`, `no_results`, `partial`, `error`, `found`) сохраняются в отчёте. Нужны разрешённые доступы к API площадки или посредника. Без них цена и спрос неизвестны.
- Для ручной проверки подключённых источников есть `POST /api/market/search` (Swagger: `/docs`). Запрос: `{"make":"Audi","model":"Q5","year":2019}`; нужен `Authorization: Bearer <access_token>`. Ответ показывает статус настройки источников, объявления, среднюю цену, ссылку, ошибки и ссылку на ручный поиск Дрома. Сама ссылка не означает, что живые объявления уже интегрированы.
- Дополнительно реализован адаптер поиска ApiAd для Авито и Дрома (`APIAD_API_KEY` в `.env`). Он отправляет провайдеру только марку, модель и год, получает цены и ссылки, дедуплицирует одинаковые ссылки и показывает полный список в карточке «Объявления». Адаптер работает только при `APIAD_ENABLED=true`; по умолчанию выключен, чтобы ключ сам по себе не запускал потенциально тарифицируемые запросы. До включения проверьте тарифы, правила использования и допустимость обработки данных у поставщика. [Документация ApiAd](https://apiad.ru/).
- Для проверки VIN предусмотрен `VIN_API_URL`/`VIN_API_KEY`. Без настройки результат остаётся «Не проверен»; случайные статусы не генерируются.

### Статус официальных источников

- Дром документирует GET `https://api.drom.ru/v1.2/bulls/search`, но запрос для проверки вернул `400` с ошибкой о недостающем `app_id`; нужен доступ/идентификатор приложения и числовой справочник марки/модели. См. [документацию Дрома](https://www.drom.ru/commerce/dromsearch/) и [справочник `ref.xml`](https://www.drom.ru/misc/autoload/).
- Официальный API Авто.ру требует авторизационный токен; публичная документация описывает справочники и количество объявлений, а не открытые карточки с ценой. См. [документацию API Авто.ру](https://yandex.ru/dev/autoru/doc/ru/) и [условия доступа](https://auto.ru/support/autoru-legal/ru/api.html).
- Прямые API Авито и СберАвто в этой сборке не подключены. Не используем HTML-скрейпинг и не выдаём поисковую ссылку за найденное объявление.

Очередь in-memory хранится в одном процессе: новая работа ждёт текущий пакет, до `MAX_CONCURRENT_FILES` файлов обрабатываются параллельно, а GigaChat отдельно ограничен `MAX_CONCURRENT_LLM_CALLS`. Для нескольких worker-процессов и сохранения очереди при перезапуске потребуется брокер. Спрос показывается только если его вернул подключённый источник; локально он не выводится из цены и не подменяется случайной оценкой. Набор документов содержит маскированные данные; распознавание следует проверять вручную по низкому confidence.

## Ограничения безопасности текущей редакции

Вход демонстрационный: пароль не проверяется, токен не является безопасной сессией, регистрации хватает любого email. Тексты документов отправляются облачному GigaChat при настройке ключа. Данные результатов сохраняются в SQLite без полноценного контроля доступа, шифрования и сроков удаления. Используйте только тестовые документы и локальное окружение.

Проверки: `.venv/bin/python -m unittest discover -s tests -v`. Моки исходного HTML сохранены в `static/mockup_original.html` как визуальный референс. Рабочая страница — `static/index.html`. В распространяемый ZIP не включены `.env`, локальная база, загрузки и пользовательские документы из `samples/`; соответствующие fixture-тесты будут пропущены, если их файлы отсутствуют.
